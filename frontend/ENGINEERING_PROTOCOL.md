# Maddy Engineering Protocol

## Purpose

This document defines the engineering workflow for every contribution made to the Maddy Executive Operations System (MEOS).

The goal is simple:

Build deliberately.
Build transparently.
Build recoverably.

---

## Governing Authority

Every feature must trace back to one or more governing documents.

1. Engineering Constitution
2. Maddy Creed
3. Article I – Office of the Executive Director
4. Article II – Executive Operations
5. Technical Blueprint
6. Development Standards

If a proposed feature conflicts with these documents, the documents govern.

---

## Development Workflow

Every mission follows the same process.

1. Identify the governing authority.
2. Define one mission.
3. Produce one commit.
4. Test the result.
5. Receive Executive verification.
6. Freeze the commit.
7. Begin the next mission.

---

---

## Engineering Principles

- One mission at a time.
- One commit at a time.
- No feature creep.
- No orphan code.
- Every feature has documented authority.
- Every decision becomes institutional memory.
- Git is the permanent history of the project.

---

## Executive Principle

Conversation is the workshop.

Documentation is the law.

Git is the institutional memory.
